# AGENTS.md — examples/demo-shop/

The example product: `services/` is the **system under test**, `api-tests/` shows how a product team
uses the framework. Read the root `AGENTS.md` first; these rules add to it.

## Layout

| Path | What | Edit? |
|------|------|-------|
| `services/{Auth,Product,Order}Service` | ASP.NET Core minimal APIs (ports 5300/5100/5200) | only when the task is about the example services — ask first |
| `docker-compose.yml` | SQL Server + Redis + services | ask first |
| `api-tests/DemoShop.Clients/swagger/*.json` | **curated contracts** | yes, deliberately (see below) |
| `api-tests/DemoShop.Clients/Dtos/*.cs`, `Routes.cs` | hand-written DTOs mirroring the contracts, route constants | yes |
| `api-tests/DemoShop.Steps/ServiceSteps/*.cs` | one step class per service | yes |
| `api-tests/DemoShop.Steps/Builders/*/Generated/*.g.cs` | generated builders | **never** — regenerate |
| `api-tests/DemoShop.Steps/Builders/Custom/*.cs` | hand-written builder partials | yes |
| `api-tests/DemoShop.Tests/**` | fixtures, `EndToEnd/` flows, `GlobalSetup`, `TestIdentities` | yes |
| `api-tests/DemoShop.Tests/Generated/*.cs.txt` | generated scaffolds (not compiled) | **never** — copy into real fixtures |
| `collections/**`, `perf/k6/**` | generated by `tools/` | **never** — regenerate |
| `api-tests/generator.json`, `openapi-tools.json` | generator / tools config | yes, when onboarding services |

## Contract rules

- The contract states `required` request fields, every documented status code (401 on secured
  operations, 403 where roles apply), real nullability, enums **as integers** (that is what the
  services send: `OrderStatus`, `ShippingMethod`) and error bodies (`ErrorResponse` on 400/404/409).
- Contract validation runs in **Fail** mode on every response (`appsettings.test.json`). A contract
  violation is a finding: fix the contract or report the service bug — never opt out to get green.
- Contract change → DTOs → `generator.json` run → Python generators → commit everything together.
- After `scripts/refresh-swagger.ps1`, review the diff and keep the curated parts.

## Test rules

- Fixtures use steps; identities via `AsIdentity(TestIdentities.Admin)` / `RegisterIdentityAsync`.
  `DELETE /api/products/{id}` is admin-only — cleanup of products must run as admin.
- Own your data: unique names/categories/e-mails per test; `RegisterCleanup` immediately after create.
- Partial updates use plain DTOs (`new UpdateOrderRequest { Status = … }`), not builders.
- Known demo simplifications (anyone can register as Admin, orders don't decrement stock, …) are
  listed in `README.md` here — don't "fix" them silently; tests may rely on them.

## Flows and business rules

- `api-tests/domain-rules.md` holds the intended behaviour (rule IDs); `api-tests/flows/*.md` the e2e
  flows. Expectations in e2e tests come **only** from these files — never from observed responses.
- A disagreement between system and flow/rule is reported, not "fixed" in the test.
- New flow → flow file first (template: `.claude/skills/write-e2e-flow/flow-template.md`), then the test.
